校园教学楼导航 MVP 产品设计文档

一、产品概述

一个面向学生的教学楼室内导航工具，帮助用户知道自己当前在哪栋楼、哪层、附近哪个教室，并能用文字指令走到目标教室。

MVP 不做地图绘制、不做平面图、不做自动路径生成，只基于已有数据完成：
定位当前位置 -> 用户修正 -> 搜索目标 -> 生成文字导航。

二、核心目标

用户进入教学楼后，能自动判断大概在哪栋楼、哪层。

系统默认一个“最近位置”，用户可手动修改。

用户输入或选择目标教室。

系统用中文名和“经过哪些教室、楼梯口、电梯口”生成文字导航。

不使用“前方 300 米”这类距离描述。

不依赖教室编号，导航中直接说教室中文名。

三、目标用户与场景

用户：

新生、外校访客、不熟悉教学楼的学生。

需要快速找到某间教室、办公室、实验室的人。

典型场景：

第一次来 A 栋，不知道自己在几楼。

知道目标叫“物理实验室”，但不知道在哪。

从 1 楼要到 3 楼某间教室。

从 A 栋要到 B 栋某间教室。

四、MVP 范围

做：

GPS 判断楼栋。

高度传感器判断楼层。

默认最近元素作为当前位置。

用户可手动修改楼栋、楼层、当前位置。

搜索或选择目标位置。

生成同层、跨层、跨楼的文字导航。

导航中列出中间经过元素的中文名。

使用预置数据结构，前端直接读取。

不做：

地图绘制编辑器。

平面图展示。

自动生成数据文件。

自动生成门、边、路径。

AR、3D、实时跟踪。

高精度室内连续定位。

全校园一次性覆盖。

后台管理系统。

五、核心概念与数据模型

楼栋 Building：

id

name，如 A栋

polygon，楼栋多边形，经纬度点串

floors，楼层列表

楼层 Floor：

id

level，如 1、2、3

relative_height_m，相对高度，用于判断楼层

elements，该层所有元素

元素 Element：

id

type，取值：room、office、stair、elevator、entrance、toilet

name，中文名，如“物理实验室”“东楼梯口”

points，经纬度点串

说明：

所有图形统一用经纬度点串表示。

楼栋是多边形，教室、楼梯、电梯、走廊等也是点串。

id 内部关联用，前端导航不展示编号。

name 用于展示和导航文案。

六、功能设计

6.1 定位

楼栋定位：

使用 GPS。

判断用户点是否在楼栋多边形内。

在哪个楼栋多边形内，就锁定哪栋楼。

室内 GPS 漂移时，保持最后锁定的楼栋。

楼层定位：

使用手机高度传感器，优先气压计。

读取每层 relative_height_m。

将当前高度匹配到最接近的楼层。

没有气压计或数据不准时，用户手动改。

当前位置：

在当前楼层所有元素中，找离用户最近的元素。

直接作为默认当前位置，不弹窗、不推荐、不打断。

例如默认显示：当前位置：A栋 · 3楼 · 语文教研室。

用户修正：

顶部位置卡片提供“修改”。

可修改三级：楼栋、楼层、当前元素。

手动修改优先，短时间内不被自动结果覆盖。

用户点“重新定位”后，才重新采用 GPS 和高度结果。

6.2 目标选择

支持搜索中文名，如“物理实验室”。

支持从列表选择目标。

MVP 不要求用户输入教室编号。

未来可支持编码，如 a 表示教室、b 表示办公室、k 表示楼梯口。

6.3 导航指令生成

原则：

不用米数。

不用教室编号。

按物理顺序列出中间经过的元素中文名。

用“左转、右转、向前、往回、左手边、右手边、隔壁”描述。

楼梯口、电梯口作为关键转向点。

同层导航示例：
从当前位置出发，沿走廊往右走，经过语文教研室、数学教研室，目标物理实验室在左手边。

相邻示例：
目标物理实验室就在隔壁。

中间元素太多：
经过语文教研室等 6 个教室，目标物理实验室在右手边。

跨层导航示例：
先走到东楼梯口，上到 3 楼，出楼梯后沿走廊往右走，经过语文教研室、数学教研室，目标物理实验室在左手边。

跨楼导航示例：
先出 A 栋，前往 B 栋，进楼后上到 2 楼，出楼梯后沿走廊往左走，经过语文教研室、数学教研室，目标物理实验室在右手边。

排序方式：

计算同层元素的质心。

沿走廊主轴方向投影排序。

得到类似顺序：入口 -> 语文教研室 -> 数学教研室 -> 东楼梯口 -> 化学实验室 -> 物理实验室 -> 电梯口。

从当前位置到目标，取中间这段，按顺序生成文案。

七、用户流程

打开应用
-> 自动定位楼栋、楼层、默认当前位置
-> 展示位置卡片，可修改
-> 搜索或选择目标
-> 生成文字导航
-> 用户按文字走到目标
-> 可重新定位或修改位置

八、页面结构

当前位置：A栋 · 3楼 · 语文教研室
[修改] [重新定位]

搜索目标：____________
[搜索]

导航指令：
先走到东楼梯口，上到 3 楼，
出楼梯后沿走廊往右走，
经过语文教研室、数学教研室，
目标物理实验室在左手边。

九、非目标

不做室内连续定位。

不做高精度教室级自动定位。

不做 AR 实景导航。

不做 3D 地图。

不做实时语音转向。

不做全校园一次性覆盖。

不做可视化绘图编辑器。

不做自动生成路径和边。

十、未来规划

可视化编辑器：

地图上画楼栋多边形。

楼层里用彩色方框画教室、楼梯、电梯、走廊。

教室批量等分。

自动生成：

门节点。

同层边。

跨层边。

默认最近元素。

平面图展示。

教室编码：a 教室、b 办公室、k 楼梯口。

课表导入，下一节课一键导航。

到达确认和众包纠错。

蓝牙/WiFi 辅助定位。

多楼栋扩展和后台管理。

十一、MVP 验收标准

进入 A 栋，能自动识别楼栋。

上到 3 楼，能估算楼层。

默认当前位置基本合理，错了能手动改。

搜索“物理实验室”能匹配到目标。

同层导航能列出中间经过的中文名。

跨层导航能提示先上/下到几楼。

跨楼导航能提示先出楼、前往目标楼栋。

全程不用米数、不用教室编号。

用户改完位置后，导航立即重算。

十二、一句话总结

MVP = GPS 判楼栋 + 高度判楼层 + 默认最近元素 + 用户可改三级位置 + 搜索目标 + 中文文字导航。
导航只列中文名，不说米数，不用教室编号，先把“能找到教室”这件事跑通。
