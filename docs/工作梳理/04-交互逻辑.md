# 04 · 交互逻辑

本文写**点下去会发生什么**：每个页面的手势路由、状态机、反馈文案、边界处理。

改交互之前先看这里。很多看起来「顺手加一下」的改动会撞上后面的硬约束
（比如 §2.2 的手势互斥、§5 的撤销顺序）。每个约束后面都写了**为什么**。

---

## 一、全局骨架

### 1.1 三个页签 + 一个子页

```
Scaffold（统一 Snackbar 宿主）
 └── Box
      ├── 地图编辑器（永远在组合树里，只有「地图」页签时可见）
      ├── SaveableStateHolder
      │     └── when {
      │           设置页    -> SettingsScreen
      │           首页      -> HomeScreen
      │           地图      -> Unit（地图已常驻在上面）
      │           我的      -> ProfileScreen
      │         }
      └── 悬浮底部导航（最后画，永远在最上层且可点）
```

- 底部导航只有三个页签：**首页 / 地图 / 我的**。「地图」用画笔图标。
- 设置是「我的」的子页，用独立的 `showSettings` 标记。
- **在设置页里也显示底部导航**：点任意页签会退出设置页。避免出现「没有退路」的死角。

### 1.2 切页签时的状态保持

| 页面 | 保持方式 | 效果 |
| --- | --- | --- |
| 首页 / 我的 | `SaveableStateHolder` 按 `pageKey` 存取 | 滚动位置、搜索框内容不丢 |
| 地图 | **常驻组合树** | `MapView` 对象、相机、overlay 全不变 |

**地图那条是踩了两次坑之后的唯一可行做法**：一旦离开组合树，`MapView` 就会被销毁重建，
相机位置与 overlay 全丢，表现就是「切回来地图刷新了」。
早先试过把它提到 Activity 作用域（只解决状态重建）、换成 `movableContentOf`
（`AndroidView` 移动时 View 仍被重建），都不行。

实现：`active=false` 时 `AmapEditorView` 自己把 `MapView` 设成 `INVISIBLE` 并解除手势监听。
既不后台白白渲染 GL，也不会拦住别的页面的点击。

**新增页面时注意**：这条规矩意味着「地图」分支必须是 `Unit`。
如果给地图页签加一个页面内容，它会盖住常驻的地图。

### 1.3 反馈通道

| 通道 | 用途 | 位置 |
| --- | --- | --- |
| Snackbar | 操作结果（已保存 / 已撤销 / 已选中…）、引导提示 | `AppShell` 统一宿主，两个 ViewModel 的 `messages` / `toasts` 都汇进去 |
| 卡片内提示行 | 持久状态（定位不可用、楼层待确认） | `PositionCard` 下方的 `positionHint` |
| 底部状态条 | 绘制中的实时状态（「已落 2 个点，至少还要 1 个」） | 编辑器底部 |
| 按钮可用性 | 不能做的操作直接灰掉 | 圆形工具按钮、成面按钮 |

**原则**：能直接灰掉的就灰掉；灰不掉但用户会尝试的，必须给一句 Snackbar。
**永远不要静默失败**。

## 二、地图编辑器的手势路由

### 2.1 两条互斥的路

`AmapEditorView` 里只有一种手势通道可用：

| `usesDragGesture` | AMap 配置 | 收到什么 |
| --- | --- | --- |
| `false` | `setOnMapClickListener { onMapClick }` | **点击** → `onTap(lngLat)` |
| `true` | `setOnMapTouchListener { DOWN/MOVE/UP }` + `setOnMapClickListener(null)` | **按下 / 移动 / 抬起** → `onDragStart/Update/End` |

**为什么用 `setOnMapTouchListener` 而不是只靠 `setOnMapClickListener`**：
后者只有「点击」一个语义，拿不到按下 / 移动 / 抬起，做不了拖拽框选。

**为什么拖拽期间要关掉地图平移**：`ACTION_DOWN` 先把
`isScrollGesturesEnabled = false`，`ACTION_UP` / `CANCEL` 再打开。
否则手指一拖地图就跟着走，根本框不准。

### 2.2 `usesDragGesture` 的取值 —— **别改错这一条**

| 模式 | 值 | 为什么 |
| --- | --- | --- |
| 教学楼 | `true` | 拖出矩形外轮廓 |
| **自由轮廓** | **`false`** | 钢笔：一次点击 = 一个顶点 |
| 教室 / 办公室 | `true` | 拖出矩形 |
| 圆形区域 | `true` | 按下 = 圆心，拖出 = 半径 |
| **自由多边形** | **`false`** | 钢笔：同上 |
| 楼梯口 / 卫生间 | `false` | 点一下落点 |
| **编辑模式（任意模式）** | **`true`** | 拖顶点 / 拖整体平移 |

> ⚠️ **这是本项目最容易改错的一处**。曾经写成 `!mode.isPoint`，
> 于是钢笔模式装了拖拽监听、**永远收不到点击**，
> 表现为「切到自由多边形之后点地图一点反应都没有」。
> 已经有 `钢笔模式必须走点击这条路而不是拖拽` 这个回归用例挡着。

### 2.3 地图点击（`usesDragGesture == false` 时）

```
onTap(point)
 ├─ 编辑模式 ────────► 记 editAnchor = point；selectAt(point)
 ├─ 不能落笔（没选楼栋）► Snackbar「请先选定要画在哪栋楼，再开始绘制」
 ├─ 钢笔模式 ────────► appendPenPoint(point)
 ├─ 不是单点模式 ────► Snackbar「按住拖动框出范围（不用逐点点选）」（防御性分支）
 └─ 单点模式 ────────► commitPoints([point])  ← 楼梯口 / 卫生间落点完成
```

**`appendPenPoint` 的细节**：

- 与上一个点距离 < `PEN_MIN_STEP_M = 1 m` → Snackbar「和上一个点太近了，往外点一点」，
  **不落点**。手指在同一个位置点两下会落出几乎重合的点，那些零长度边会让
  `isValidPolygon` 判不过，而用户完全看不出原因。
- 落点后 Snackbar 报进度：「已落下第 2 个点，至少还要 1 个」/
  「已落下第 5 个点，点『成面』闭合；还能继续加点」。

### 2.4 拖拽绘制（`usesDragGesture == true`）

```
DOWN  → onDragStart(p)
         ├─ 编辑模式 ─────► onShapeDragStart(p)   ← 见 §3
         ├─ 钢笔模式 ─────► Snackbar「自由多边形是『连续点』画法…」，不进入拖拽
         ├─ 单点模式 ─────► 忽略
         ├─ 不能落笔 ─────► Snackbar「请先选定要画在哪栋楼，再开始绘制」
         └─ 否则 ─────────► dragStart = p, draftPoints = [p]
MOVE  → onDragUpdate(p) → draftPoints = previewPoints(mode, dragStart, p)
UP    → onDragEnd(p)
         ├─ 矩形：跨度 < MIN_DRAG_SPAN_DEGREES(1e-5) ──► 清空草稿 + Snackbar「拖动范围太小…」
         ├─ 圆：点数 < 3（半径几乎为 0）────────────► 清空草稿 + Snackbar「拖动范围太小，按住往外拖出半径」
         └─ 否则 ─────────────────────────────────► 保留草稿并直接 finishDraft()
```

**两个关键点**：

1. **圆不适用「对角跨度」判定**。矩形看的是对角跨度，圆的半径小但跨度可能够，
   所以 `spanTooSmall` 只对矩形生效，圆用「点数够不够」判。
2. **松手即成型**，不需要再点「成面」。上一步只是预览，
   用户可以一路拖着调，松手就定格。成面按钮主要是给钢笔用的。

### 2.5 实时预览

| 画法 | 预览点串 |
| --- | --- |
| 矩形 | `rectangleFromCorners(start, end)` → 4 个角 |
| 圆 | `circleFromCenter(start, end)` → 32 个点 |
| 点 / 钢笔 | `listOf(start)`（钢笔实际走 `onTap` 累加） |

**`circleFromCenter` 在局部米坐标里算半径**，不是直接对经纬度取差值 ——
后者会因为「一度经度 ≠ 一度纬度」而变成椭圆（纬度 23° 处差约 8%）。
`rotate` / `translate` 同理。

### 2.6 每次改动整体重画

地图覆盖物**每次状态变化就清空 overlay 后整体重画**，不做增量更新。
元素只有几十个，重画开销可忽略，换来的是不需要维护「哪个 overlay 对应哪个顶点」的
增量状态 —— 那种写法很容易留下幽灵多边形。**只清 overlay、不动相机**，
所以用户拖地图时不会被拉回原位。

需要移动相机时走 `centerRequest`（带自增 token，UI 消费一次后调 `onCenterConsumed`
把它置空，保证同一个坐标也能重复触发）。

## 三、编辑形状的手势模型

### 3.1 进入与退出

- 点右侧「编辑形状」按钮 → `setEditMode(true)`：
  清空草稿与 `editAnchor`，Snackbar「点一下图形选中它；再点一下某个顶点，就能在那附近加点 / 删点」。
- 再点一次 → `setEditMode(false)`：**清掉选中与 `editAnchor`**
  （不清锚点的话，工具按钮会作用到一个用户看不见的位置）。
- **换绘制模式会自动退出编辑模式**（`setMode` 里做）：
  避免「以为在画新的、结果在改旧的」。

### 3.2 选中

`selectAt(point)` 的命中优先级：**楼层元素 > 楼栋外轮廓**。

理由：元素画在轮廓里面，用户想点的多半是那个小的。

- 元素：只找「点串到该点的距离 ≤ `SELECT_TOLERANCE_M = 8 m`」中最近的一个；
- 轮廓：同理，但只在本楼栋有合法多边形时算；
- 点在图形**内部**算距离 0（`Geo.containsPoint`）；
- 都没命中 → 清空选中 + Snackbar「这里没有图形，点在图上的色块里试试」。

选中后同时把 `targetBuildingId` / `floorLevel` / `draftName` 对齐到该图形 ——
这样接下来的操作上下文是自洽的。

### 3.3 拖拽（一次手势 = 一步历史）

```
onShapeDragStart(p)
 ├─ 没有选中图形 ──► selectAt(p)，不进入拖拽
 └─ 有选中 ────────► recordHistory()   ← 整个手势只记一次
                      shapeDrag = ShapeDrag(start = p,
                                            originPoints = 选中图形的原始点串,
                                            vertexIndex = nearestVertexIndex(p, VERTEX_HIT_M = 12 m))
onShapeDragUpdate(p)
 ├─ vertexIndex != null ──► originPoints[vertexIndex] = p           （拖单个顶点）
 └─ vertexIndex == null ──► translate(originPoints, Δ东, Δ北)        （整体平移）
onShapeDragEnd() ──► shapeDrag = null
```

**为什么必须记「原始点串」而不是在上一帧结果上继续偏移**：后者会把浮点误差
一帧帧累积，图形会慢慢飘走。

**为什么整个手势只记一次历史**：否则撤销一下只退回一个像素。
（对应测试：`一次拖拽编辑只记一步历史`。）

### 3.4 加点 / 删点：靠 `editAnchor`

「加点」「删点」两个按钮**本身不知道用户想操作哪儿**，所以用「最近一次点击的位置」
（`editAnchor`）—— 用户刚点了那里，这是唯一合理的解释。

| 操作 | 前置 | 行为 | 失败提示 |
| --- | --- | --- | --- |
| 加点 | 有选中图形 | 在离锚点最近的边上插一个顶点 | 没锚点：「先在图上点一下你要加点的位置（靠近边线）」；单点元素：「单点元素没有边，不能加顶点」；离边线 > 12 m：「离边线太远，点到图形的边上再加顶点」 |
| 删点 | 有选中图形 | 删掉离锚点最近的顶点 | 没锚点：「先点一下要删掉的那个顶点」；会少于 3 个点：「再删就不成面了（至少要 3 个顶点）」；附近没顶点：「附近没有顶点」 |

两个操作都先 `recordHistory()`，且**失败时不记历史**（保持撤销栈干净）。

### 3.5 旋转

- 每次 15°（`DEFAULT_ROTATE_STEP`），绕图形自身质心。
- 单点元素没有方向：「单点元素没有方向，不需要旋转」。
- 在**局部米坐标**里旋转，直接对经纬度做旋转会得到歪掉的形状。

### 3.6 删除选中图形

- 选中是轮廓 → 删整栋楼；选中是元素 → 只删那个元素。
- 两者都先 `recordHistory()`，所以**删图形也能撤销**。

### 3.7 顶点手柄的视觉反馈

选中图形时把它的每个顶点画成白底蓝圈的小圆（半径 3.5 m）；
正在拖的那个顶点变成橙色（`#FF8A00`）白边。不选中时不画手柄，
否则一屏都是小圆点。

## 四、撤销 / 重做

### 4.1 模型

```kotlin
history:   ArrayDeque<List<EditorBuilding>>   // 每次改动前压入当前 buildings
redoStack: ArrayDeque<List<EditorBuilding>>   // 撤销时把「撤销前」压进来
MAX_HISTORY = 50
```

**核心决定：历史里存的是整份数据快照，不区分来源。**
配置里读进来的楼栋和刚画出来的一样能撤 —— 这正是用户抱怨过的那点
（旧实现只记「本次新画的点」，所以配置里的楼栋撤不掉）。

### 4.2 哪些操作会记历史

| 记 | 不记 |
| --- | --- |
| 成面（新增 / 重画轮廓） | 纯粹的选择、切模式、切楼层 |
| 添加楼层元素 | 失败的操作（提示后直接 return） |
| 删楼栋 / 删元素 / 删选中图形 | 切换配置文件（**整体清空**历史栈） |
| 拖顶点 / 拖整体平移（**整个手势一次**） | 保存 |
| 插点 / 删点 / 旋转 | |

### 4.3 撤销的优先级：钢笔草稿优先

```
undo()
 ├─ 有钢笔草稿（isPen 且 draftPoints 非空）──► 退掉最后一个点
 │                                            Snackbar「已退回上一个点（还剩 2 个）」
 │                                            / 「已清掉草稿」
 ├─ 历史栈为空 ─────────────────────────────► Snackbar「没有可撤销的操作」
 └─ 否则 ──────────────────────────────────► 弹历史栈恢复 buildings
                                              Snackbar「已撤销」
```

**为什么钢笔要特殊处理**：用户说「撤销按钮不好用」，最常见的就是画多边形时点错一个。
如果撤销一下子把整栋楼退回上一步，损失太大。

为此 `canUndo` 把「有钢笔草稿」也算作可撤销，并且 `setMode` / `cancelDraft` /
`appendPenPoint` 都会重算它 —— 草稿没了按钮就该灰掉。

### 4.4 重做

- 撤销把「撤销前的 buildings」压进 `redoStack`；
- **任何新的改动都会清空 `redoStack`**（新分支让旧的重做失去意义）；
- 恢复的只是 `buildings`，不动草稿 —— 重做的是「数据」，不是「手势」。

### 4.5 切换配置会清空两个栈

否则会出现「在新学校里撤销，结果退回上一所学校」的数据错乱。

## 五、绘制到成面的完整流程

```
1. 右上角下拉选模式
2. （楼层内元素）点底部「清单」→ 选目标楼栋 → 选楼层
3. 在地图上画：
     矩形 / 圆 ──► 按住拖 → 松手
     钢笔 ──────► 连续点 → 点「成面」
     单点 ──────► 点一下（立刻完成，不弹命名框）
4. 矩形 / 圆 / 钢笔会弹命名框：
     教学楼 / 自由轮廓模式额外显示「楼层数」（可 +/- 步进）
     确定 → onNameChange + onFloorCountChange + finishDraft()
5. 底部状态条实时显示「还差什么」，右侧「成面」按钮在 `canFinishDraft && canDraw` 时才可点
6. 底部「保存导入」写文件并立刻生效
```

### 5.1 底部状态条文案（`statusLine`）

按优先级从上往下判：

| 条件 | 文案 |
| --- | --- |
| 不能落笔 | 先点「清单」选一栋楼，{模式名}要画在楼里 |
| 单点 + 跨层 | 点一下放置楼梯口，将覆盖 2→4 楼 |
| 单点 | 点一下放置楼梯口（不用拖、不用画边界） |
| 钢笔 + 草稿为空 | 连续点出自由多边形的每个角（像钢笔工具），点够 3 个再按「成面」 |
| 钢笔 + 点不够 | 已落 2 个点，至少还要 1 个 |
| 钢笔 | 已落 4 个点，可继续加点，或按「成面」闭合 |
| 拖拽 + 草稿为空 + 教学楼 | 按住拖动框出楼栋外轮廓（也可以只拖一个大概范围） |
| 拖拽 + 草稿为空 | 在「A栋」3 楼按住拖出教室范围 |
| 点不够 | 拖动的范围太小，往对角方向多拖一点 |
| 其他 | 范围已框好，点「成面」确认 |

### 5.2 命名弹窗

- 名称为空 → 用模式名兜底（「未命名楼栋」/「教室」）。
- **同名楼栋再画一次 = 重画轮廓，不是新增一栋**，并且**保留已有的楼层元素**
  （所以编辑轮廓不会把那一层画好的教室弄丢）。
- 楼层数夹在 1..`MAX_FLOOR_COUNT = 100`。

### 5.3 保存

```
save()
 ├─ buildings 为空 ──► Snackbar「还没有画好的楼栋，先在地图上拖出轮廓」，不写文件
 └─ 否则 ──► 写入当前配置（内部私有 + 外部镜像）
              ├─ 过滤掉「既没有合法轮廓、也没有任何元素」的空壳楼栋
              ├─ 先写 .tmp 再 renameTo，避免半截 JSON 弄坏原数据
              ├─ 外部那份写失败只降级为 warning
              └─ 通知 AppContainer 重新装配仓库 → 首页/导航立刻生效
```

Snackbar 会报出内部路径与外部路径（如果有），让用户知道文件在哪、怎么取走。

### 5.4 空壳楼栋为什么不留

用户只点了一下没拖出面积时，`buildings` 里可能留下一个多边形为空的楼栋。
它既不能导航也没有轮廓，写进文件只是噪声，所以 `saveActive` 里过滤掉。

## 六、首页交互

### 6.1 进入页面

自动定位 → 锁楼栋 → 定楼层 → 自动选该层最近的元素作为当前位置 → 渲染。
全过程**不弹窗、不打断**。

### 6.2 修改位置

点「修改位置」→ 底部弹层 → 楼栋 / 楼层 / 当前位置三级联动下拉 → 确定。

- 确定后 `onEditConfirm` → 写入 DataStore → **导航立即重算**（纯函数派生，不需要手动刷新）
  → Snackbar「位置已更新」。
- 手动结果**永远优先**于自动结果，且重启 App 仍生效。
- 定位不可用时这是唯一的出路，所以提示文案会明确指向这个按钮。

### 6.3 重新定位

点「重新定位」→ 清空手动修正、楼栋锁定、气压基准 → 重新订阅定位流与气压流
→ Snackbar「已重新定位」。

**这是唯一会覆盖手动修改的动作**（所以文案里要强调）。

### 6.4 搜索目标

```
输入 → 边输边出候选（中文名 + 所属楼栋·楼层）
回车 / 点「导航」 → onNavigate(trimmed) → 清空输入框 + 关闭候选
点候选行 → 用该元素名提交
点快捷目标胶囊 → 直接提交
```

- 提交后强制刷新一次候选（`refreshTick`）：同样的关键字也要重算，因为当前位置可能变了。
- 找不到 → Snackbar「没找到这个位置」。

### 6.5 导航结果的四种状态

| 状态 | 渲染 |
| --- | --- |
| `Empty` | 不显示卡片（避免首页出现空置的大块区域）；但楼层未知时给一句引导 |
| `Loading` | 「定位中，稍后给出导航指令…」 |
| `Arrived` | 「你已经在 X 了。」 |
| `Unavailable` | 直接显示原因 |
| `Ready` | 导航指令卡片，目标中文名用主色高亮 |

### 6.6 位置提示行（`positionHint`）的优先级

```
定位不可用（权限 / 服务关闭 / 无 provider）  ← 最高，这时候「定位中…」是假象
  ↓
正在定位中（返回 null，不显示提示行）
  ↓
没取到楼栋
  ↓
没有气压计
  ↓
气压稳定中 / 气压不可靠
  ↓
楼层仍为空
  ↓
来源是手动 → 「已按你的修改定位，点『重新定位』才会重新采用 GPS。」
  ↓
来源是上次锁定 → 「室内信号弱，沿用上次锁定的楼栋。」
```

## 七、设置页交互

### 7.1 高德地图 Key

- 输入框默认密码样式遮蔽，右侧「显示 / 隐藏」切换。
- 保存：`trim()` 后存 SharedPreferences → Snackbar「已保存高德 Key」；空值 →
  Snackbar「Key 不能为空」，不保存。
- 清除：清空输入框 + 存储 → Snackbar「已清除高德 Key」。
- 从设置页返回时 `refreshApiKey()`，因为用户可能刚填 / 刚清。

### 7.2 搜索 Key（Web服务）

同上，文案区分：「已保存 Web服务 Key，搜索将使用高德 POI 模糊匹配」/
「已清除 Web服务 Key，搜索退回系统地理编码」。

**两个 Key 互不影响**（有测试挡着）。

### 7.3 配置管理

```
● 配置（一个学校一份）
这份软件不针对某一个学校：换学校就是换一份配置。当前正在用：「editor_buildings」
┌──────────────────────────────────────┐
│ 实验中学                      使用中   │   ← 蓝框 + 「使用中」
│ 3 栋楼 · 2025-01-31 14:05             │
│ [ 复制 ] [ 改名 ] [ 删除 ]            │
└──────────────────────────────────────┘
[ 新建配置 ]
```

| 操作 | 交互 | 反馈 |
| --- | --- | --- |
| 切换 | 点整行 | Snackbar「已切换到『实验中学』」，**清空撤销栈**，通知外层重装仓库 |
| 新建 | 按钮 → 命名弹窗 → 确定 | 「已新建配置『X』」，立刻切过去，内容是空的 |
| 复制 | 行内按钮 | 「已复制为『X 副本』」并切到副本 |
| 改名 | 行内按钮 → 弹窗（预填当前名）| 「已重命名为『X』」 |
| 删除 | 行内按钮 → 二次确认弹窗 | 「已删除『X』」；删的是当前那份会自动切到剩下最新的一份 |

- **重名自动加序号**（`X-2.json`），不覆盖已有配置。
- 名字会过滤掉 `/ : * ? " < > |` 等非法字符，并自动去掉用户可能带的 `.json` 后缀。
- **改名成同一个名字是空操作**（不会多出一份 `X-2.json`）。
- 文件名读不出来的配置在列表里标成「文件读不出来（可能不是配置文件的 JSON）」，
  点它不会崩，只是读出来是空的。

### 7.4 配置相关的两个自查 bug（已修，有回归用例）

| 症状 | 根因 |
| --- | --- |
| 一打开设置页就闪退 | `list()` 与 `activeFileName()` 互相调用 → `StackOverflowError`。改成 `list()` 只读原始配置名，不回退 |
| 点「改名 → 直接确定」，配置莫名多出一份 `xxx-2.json` | `rename` 先查重再判同名，顺序反了。改成先比显示名 |

## 八、我的页交互

- 「定位测试」是一个可折叠区块，展开后显示原始经纬度、水平精度、provider、
  最近更新时刻、原始气压、推算高度、是否有气压计、当前判定到的楼栋 / 楼层 / 元素。
- **为什么要有**：室内导航出问题时，第一件要判断的是「传感器到底有没有数据」，
  而首页只展示经过业务解读的结论（A栋 · 3楼 · 语文教研室），看不出原始值。
- 「设置」是入口行，点进设置子页。

## 九、地图页搜索交互

```
收起态：   [ 🔍 搜索地点 ]                    ← 白胶囊，点一下展开
展开态：   [ 🔍 [输入框] ✕/转圈 ] [取消]      ← 自动聚焦弹键盘；模式下拉宽度动画到 0
           ┌────────────────────────────┐
           │ 某某大学  广东省深圳市…      │    ← 结果面板从搜索框下沿展开
           │ …                          │
           └────────────────────────────┘
```

- **防抖 300 ms**（`SEARCH_DEBOUNCE_MS`）：高德 Web API 有配额、Geocoder 有频率限制，
  每敲一个字查一次容易被限流。
- 搜索中把尾部图标换成 16 dp 转圈；有内容时显示「清空」。
- 点结果 → 把地图移过去（`onGoToPoint`）+ 输入框填上该地点名 + 收起面板。
- 「取消」收起面板并清空结果。
- **不新开一层全屏页面**，也**不用半透明全屏遮罩** —— 后者会把地图糊一层白，
  用户挑地点时反而看不到地图。

## 十、边界与容错清单

| 情况 | 行为 |
| --- | --- |
| 没填高德 Key 进地图页 | 显示引导卡 + 「去设置里填写 Key」，**不白屏** |
| 本机不支持地点搜索 | 搜索框文案变成「本机不支持地点搜索」并禁用 |
| 定位权限被拒 / 定位服务被关 | 位置卡片给出对应文案，指向「修改位置」手动兜底 |
| 本机没有气压计 | 「本机没有气压计，请在『修改位置』里选择楼层」 |
| 气压数据不可靠 | 「气压数据不太准，建议点『修改位置』确认楼层」 |
| 定位中途被关掉 | `locationUpdates()` 发出 `Unavailable`，`isLocating` 必定复位，不卡在「定位中…」 |
| 配置文件损坏 | 列表标成损坏；读取时返回空配置，**不抛异常** |
| 指定的配置文件被删 | 回退到目录里最新的一份 → 再回退默认文件名 |
| 一份配置都没有 | 编辑器为空；仓库退回只用 assets 内置数据 |
| 删除正在用的那份配置 | 自动切到剩下最新的一份 |
| 写外部目录失败（存储未挂载） | 只降级为 warning，内部那份仍然是权威 |
| 图形太小 / 只点了一下 | 提示「拖动范围太小…」，不留下针尖大的图形 |
| 想删到少于 3 个顶点 | 拦住并说明「至少要 3 个顶点」 |
| 单点元素上加点 / 旋转 | 拦住并说明原因（没有边 / 没有方向） |
| 点空白处想选中 | 「这里没有图形，点在图上的色块里试试」 |
| 高德 Key 平台选错 | 报 `INVALID_USER_KEY` —— 那不是 Key 失效，是类型不对（设置页里有说明） |
