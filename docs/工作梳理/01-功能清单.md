# 01 · 功能清单

按「用户能干什么」组织，不按代码文件组织。每条写清**入口 → 行为 → 怎么验证**。

状态图例：

| 标记 | 含义 |
| --- | --- |
| ✅ | 已完成，有自动化测试，构建全绿 |
| 🟡 | 已实现，但**没有真机验证**（需要设备 / 高德 Key） |
| ⛔ | 明确不做 |
| ➕ | 自加功能（原始文档里没有，或文档说「不做」但做了） |

## 一、定位与「我在哪」

### 1.1 GPS 判定在哪栋楼 ✅

- **入口**：进入 App 自动执行，无需操作。
- **行为**：拿到经纬度后，用**射线法**判断点是否落在某栋楼的外轮廓多边形内；命中即锁定该楼栋。
- **容错**：室内 GPS 漂移导致出多边形时，**保持最后锁定的楼栋**（不来回跳），
  并在位置卡片提示「室内信号弱，沿用上次锁定的楼栋」。
- **验证**：`GeoTest`、`CampusRepositoryTest`、`NavViewModelLocationFallbackTest`。

### 1.2 气压计判定在哪一层 ✅

- **入口**：自动。
- **行为**：`TYPE_PRESSURE` → 滑动平均 → 用 `h = 44330·(1 − (P/P0)^(1/5.255))` 换算相对高度
  → 与各层 `relative_height_m` 比最近的一层。
- **基准**：`P0` **不硬编码**。用户在「修改位置」里选定楼层时，把当时的气压记为该层基准。
- **滞后**：切换楼层要比当前层「近」超过 1.5 米才允许，避免两层之间来回跳。
- **兜底**：离所有层都超过 6 米 → 返回「无法判断」，交给手动选择，不硬套一个楼层。
- **无气压计**：提示「本机没有气压计，请在『修改位置』里选择楼层」。
- **验证**：`FloorMatcherTest`（13 例）。⚠️ 四个参数（窗口 8 / 阈值 1.5 m / 最大偏差 6 m /
  层高 4 m 假设）都是估值，需要真机调。🟡

### 1.3 默认当前位置 ✅

- **行为**：楼层确定后，自动选中该层里**离用户最近的元素**作为当前位置，不弹窗、不打断。
- **验证**：`CampusRepositoryTest`（`nearestStandableElement`）。

### 1.4 三级手动修改 ✅

- **入口**：首页「当前位置」卡片 → **修改位置**。
- **行为**：底部弹层，**楼栋 → 楼层 → 当前位置** 三级联动下拉，确定后立即重算导航。
- **优先级**：手动结果**永远优先**于自动结果，且会持久化（DataStore），重启 App 仍生效。
- **验证**：`NavViewModelLocationFallbackTest`（含「定位不可用时仍能手动完成导航」）。

### 1.5 重新定位 ✅

- **入口**：首页「当前位置」卡片 → **重新定位**。
- **行为**：清空手动修正、楼栋锁定、气压基准，重新采用 GPS 与气压计结果。
- **注意**：这是**唯一**会覆盖手动修改的动作。
- **细节**：之前判定过「定位不可用」时会重新订阅定位流 ——
  否则用户去系统设置里打开定位后，点「重新定位」永远恢复不了。

### 1.6 定位不可用时的明确提示 ✅➕

- **行为**：区分三种原因给不同文案，**不显示假的「定位中…」**：

  | 原因 | 文案 |
  | --- | --- |
  | 没有权限 | 没有定位权限，请点"修改位置"手动选择当前位置。 |
  | 系统定位服务已关闭 | 系统的定位服务已关闭，请点"修改位置"手动选择当前位置。 |
  | 本机没有 provider | 本机无法自动定位，请点"修改位置"手动选择当前位置。 |

- **为什么是自加**：原始方案没写这个分支，实测发现「中途关掉定位服务」会让界面永远转圈。
- **验证**：`NavViewModelLocationFallbackTest`（6 例）。

## 二、导航

### 2.1 搜索目标 ✅🟡

- **入口**：首页「要去哪里」卡片输入框，或地图页顶部搜索框。
- **行为**：
  - 首页：边输边给候选（中文名 + 所属楼栋楼层），回车 / 点「导航」取最佳匹配；
  - 地图页：就地展开成输入框，**300 ms 防抖**后查询，结果从搜索框下面拉出来。
- **后端**：配了高德「Web服务」Key → 高德 POI 文本搜索（能容忍少写字、同音字）；
  没配 → 退回系统 `Geocoder`（只做精确地址解析，少一个字就搜不到）。🟡
- **匹配分级**：完全相等 → 包含 → 前缀 → 后缀（后缀候选会砍到 3 个字以内再比）。
- **验证**：`CampusRepositoryTest`、`BuildingsDataTest`。

### 2.2 快捷目标 ✅

- **入口**：首页「快捷目标」下方一排胶囊按钮。
- **行为**：点一下立即导航，不用打字。候选由 `CampusRepository.quickTargets()` 给出。

### 2.3 三种导航路线 ✅

| 场景 | 输出 |
| --- | --- |
| 同层 | 沿走廊向东/西走，经过 A、B，目标在左手边 / 右手边 / 正前方 |
| 跨层 | 先走到楼梯口，上/下到 N 楼；出楼梯后继续同层指引 |
| 跨楼 | 先出 A 栋，前往 B 栋（楼栋级指引，不做室外路径） |
| 已到达 | 你已经在 X 了。 |

- **验证**：`NavigationEngineTest`。

### 2.4 文案硬约束 ✅

- **不许出现米数**、**不许出现教室编号**（a101 之类）。
- 只用中文名 + 「左手边 / 右手边 / 正前方 / 隔壁」这类相对描述。
- **验证**：`NavigationEngineTest` 里有正则反向断言 `\d+\s*(m|M|米)`。

### 2.5 导航自动重算 ✅

- **行为**：导航结果是 `(当前位置, 目标)` 的**纯函数派生状态**，任何一方变化都自动重算，
  不需要手工触发刷新。
- 这就是验收标准「用户改完位置后，导航立即重算」的实现方式。

## 三、地图编辑器 ➕

> 产品文档把「地图绘制编辑器」列为**不做**。但那样一来每换一个学校就得手写 JSON 录数据，
> 实际不可用，所以做了。详见文末「有意偏离」。

### 3.1 地图与定位 ✅🟡

- 高德**卫星底图**全屏，关掉高德自带的缩放按钮 / 指南针 / 定位按钮（视觉语言不一致）。
- 进页面自动定位，**第一次**取到定位时把地图移过去（不是每次都拉回原位）。
- 右侧「定位」按钮随时把地图移回我的位置。🟡

### 3.2 四种绘制画法 ✅

| 模式 | 手势 | 说明 |
| --- | --- | --- |
| 教学楼 | 按住拖出对角 | 矩形外轮廓 |
| **自由轮廓** ➕ | 连续点 | 钢笔，楼不一定是方的 |
| 教室 / 办公室 | 按住拖出对角 | 先在清单里选宿主楼栋 + 楼层 |
| **圆形区域** ➕ | 按下 = 圆心，拖出 = 半径 | 存成 32 边多边形 |
| **自由多边形** ➕ | 连续点 | 钢笔，画 L 形教室这类 |
| 楼梯口 / 卫生间 | 点一下 | 单点，画成实心圆点 |

- 楼梯额外选**起始层 + 结束层**，跨层时在覆盖的每一层都生成一份同名楼梯。
- 拖拽绘制期间**关掉地图平移**，否则手指一拖地图就跟着走，框不准。
- **验证**：`MapEditorViewModelTest`。

### 3.3 编辑已有图形 ➕

- **入口**：右侧「编辑形状」按钮 → 点选图形。
- **能做**：

  | 操作 | 手势 |
  | --- | --- |
  | 拖单个顶点 | 按住某个顶点拖 |
  | 整体平移 | 按住图形内部空白处拖 |
  | 边上插点 | 点一下边线附近 → 按「加点」 |
  | 删顶点 | 点一下顶点 → 按「删点」 |
  | 旋转 | 按「旋转」，每次 15° |
  | 删除整个图形 | 按「删除图形」 |

- **命中容差**：选中图形 8 m，顶点 / 边线 12 m。
- **为什么需要**：轮廓画歪一点是常事，重画等于把那一层的元素全丢掉。

### 3.4 撤销 / 重做 ✅➕

- **行为**：整份 `List<EditorBuilding>` 的**快照栈**（上限 50 步）+ 重做栈。
  - **不区分来源**：配置里读进来的楼栋和刚画的一样能撤 —— 这是用户明确抱怨过的一点；
  - **一次拖拽 = 一步**（否则撤销一下只退回一个像素）；
  - **钢笔草稿优先退点**：正在连点画多边形时，撤销先退掉刚落的那个点。
- **验证**：`MapEditorViewModelTest`（含「撤销能把配置里读进来的楼栋也撤回来」）。

### 3.5 绘制清单 ✅

- **入口**：编辑器底部「清单」。
- **行为**：列出所有楼栋 → 楼层 → 元素；可改楼栋楼层数、切换目标楼栋 / 楼层、
  删楼栋、删单个元素、把外部目录里被换过的配置**重新加载**。

### 3.6 保存并自动导入 ✅

- **入口**：编辑器底部「保存导入」。
- **行为**：写入当前生效的配置（**内部私有目录 + 外部镜像目录各一份**），
  立即通知 `AppContainer` 重新装配仓库 → **首页/导航立刻用上新数据**，不用重启。
- **原子性**：先写 `.tmp` 再改名，写到一半被中断也不会留下半截 JSON 把原数据弄坏。
- **过滤**：既没有合法轮廓、也没有任何元素的空壳楼栋不写进文件（只是噪声）。
- **验证**：`ConfigStoreTest`、`MapEditorViewModelTest`。

### 3.7 没配 Key 时的引导 ✅

- 没填高德 Key 时地图页**不白屏**，显示引导卡片 + 「去设置里填写 Key」按钮。
- 理由：地图 SDK 缺 Key 只会白屏，那种失败方式对用户毫无帮助。

## 四、多学校配置 ➕

> 需求原话：「配置文件不能只有一个，此软件不针对单独一个学校，我的设置页面需要有一个可以换配置的。」

### 4.1 目录结构 ✅

```
/data/data/<包名>/files/config/
  ├── editor_buildings.json     ← 默认那份
  ├── 实验中学.json
  └── ...
/sdcard/Android/data/<包名>/files/config/   ← 镜像一份，方便用数据线取走
```

### 4.2 能做什么 ✅

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| 切换 | 设置页配置卡片，点整行 | 当前生效那份用蓝框 + 「使用中」标注 |
| 新建 | 卡片底部按钮 | 建一份空配置并立刻切过去；重名自动加 `-2` |
| 复制 | 每行「复制」 | 照着改比从零画快得多 |
| 改名 | 每行「改名」 | 名字就是文件名；填同样的名字是空操作 |
| 删除 | 每行「删除」 | 二次确认；删掉当前那份会自动切到剩下最新的一份 |
| 换学校 | 把别人的 `xxx.json` 拷进外部目录 → 切换 | 不用重新装 App |

### 4.3 关键决定 ✅

- 「当前用哪一份」记在 **SharedPreferences**，不写进配置内容 ——
  配置本身应该是自包含的数据，「这台机器在看哪一份」是本地状态，混进去文件就没法互相拷贝了。
- 指定的那份被删掉 → 回退到目录里**最新的一份** → 目录为空 → 用默认文件名兜底。三级兜底。
- **切换配置会清空撤销栈**，避免「在新学校里撤销，结果退回上一所学校」。
- 切换配置后 `NavViewModel` 会跟着换数据（订阅 `AppContainer.repositoryFlow`），
  不会出现「地图是 A 校、首页还在讲 B 校」。
- **验证**：`ConfigStoreTest`（30 例）、`MapEditorViewModelTest`。

## 五、设置（我的 → 设置）

### 5.1 高德地图 Key（Android 平台）✅

- 用户在 App 里填，**不打进 APK**。
- 为什么：Key 是开发者凭据，打进 APK 能被反编译；而且高德 Key 与「包名 + 签名 SHA1」绑定，
  换机器 / 换签名就要换 Key，每次改代码重新打包不务实。
- 输入框默认密码样式遮蔽（设置页经常被人围观）。

### 5.2 高德搜索 Key（Web服务，可选但强烈建议）✅

- **两个 Key 必须分开**：高德的 Key 按「服务平台」区分用途，
  Android 平台的 Key **不能**用于 Web 服务，反之亦然。
- 不填 → 搜索退回系统 `Geocoder`，必须写全名且不能有同音字。
- 平台选错会报 `INVALID_USER_KEY` —— 那不是 Key 失效，是类型不对。

## 六、我的 → 定位测试 ✅

- **入口**：「我的」页里的定位测试（可折叠）。
- **展示**：原始经纬度、水平精度、provider、最近更新时刻、原始气压、推算高度、
  是否有气压计、当前判定到的楼栋 / 楼层 / 元素。
- **为什么需要**：室内导航出问题时，第一件要判断的是「传感器到底有没有数据」，
  而首页只展示经过业务解读的结论（A栋 · 3楼 · 语文教研室），看不出原始值。

## 七、明确不做

| 项 | 原因 |
| --- | --- |
| ⛔ 电梯口（elevator）/ 入口（entrance） | MVP 没有数据来源；导航算法也没真正用到（跨层换乘只用楼梯）。旧数据里残留这两种类型会**降级成教室**而不是崩溃 |
| ⛔ 自绘平面图 | 用真实卫星底图比自绘省一个数据源，也更符合「教学楼本来就真实存在」 |
| ⛔ 后端 / 云同步 / 账号 | MVP 零后端，完全离线可用 |
| ⛔ 教室编号体系 | 产品文档要求文案不出现编号，只用中文名 |
| ⛔ 导航文案里的米数 | 同上，硬约束 |
| ⛔ 室外路径规划 | 跨楼只给楼栋级指引（「先出 A 栋，前往 B 栋」） |

## 八、有意偏离原始文档

| 原始文档 | 实际做法 | 原因 |
| --- | --- | --- |
| 产品文档：「地图绘制编辑器」不做 | **做了**，并且是底部导航常驻页签 | 不做就只能手写 JSON 录数据，实际不可用 |
| 产品文档：「自动生成数据文件」不做 | **做了** `tools/gen-buildings-json.mjs`，但产物是**静态 JSON**，运行时只读不生成 | 数据是开发期产物，不是运行时能力，不违反「MVP 不做数据平台」的本意 |
| 技术方案：高德定位 SDK | 默认用系统定位，高德走**反射可选接入** | 高德 aar 只在自家仓库分发；抽成 `LocationSource` 接口后换实现不影响业务代码 |
| 技术方案：kotlinx.serialization 或 Moshi | 用 kotlinx.serialization | 与方案首选项一致 |
| 技术方案：多模块 `core-model` / `core-navigation` / `core-location` | 单 `core` 模块 + 分层包 | 方案里写了「MVP 可先单模块」，代码量还没到需要拆的程度 |
| — | **自加**圆形区域 / 自由多边形（钢笔）/ 自由轮廓 | 用户明确要求「既要有 PS 的钢笔，也要圆形和方形」 |
| — | **自加**编辑形状（拖顶点 / 插点 / 删点 / 旋转） | 用户反馈「画图组件不能旋转，也不能添加点」 |
| — | **自加**多学校配置 | 用户反馈「配置文件不能只有一个」 |
| — | **自加**定位不可用的三种明确提示 | 实测发现中途关掉定位会永远转圈 |
| 高德隐私合规 | 未做首启同意弹窗 | ⚠️ **上架前必须补**（国内商店硬性要求） |

## 九、还没做的（按优先级）

| 优先级 | 项 | 备注 |
| --- | --- | --- |
| P0 | 真机验证地图渲染 + 编辑手感 | 需要设备 + 你自己的高德 Key |
| P0 | 首启隐私政策同意弹窗 | 上架硬性要求 |
| P1 | 真机调气压计四参数 | `FloorMatcherConfig` 的窗口 / 阈值 / 最大偏差都是估值 |
| P1 | 换成真实校园测绘数据 | 现在 2 栋楼是示意数据 |
| P2 | 曲线的贝塞尔支持 | 现在圆的边都是直线段（32 边多边形）；要圆滑得给点串加控制点，属数据结构变更 |
| P2 | `connectedDebugAndroidTest` 跑 Compose 交互 | 需要设备 / 模拟器 |
| P3 | 元素规模上千后的排序缓存 | `CorridorOrder` 只依赖楼层数据，可按 `floor.id` 缓存 |
